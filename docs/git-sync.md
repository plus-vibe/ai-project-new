# Git и Codex на двух компьютерах

Git синхронизирует сохранённые коммиты через удалённый репозиторий. Для этого проекта пользователь явно выбрал публичный https://github.com/plus-vibe/ai-project-new. Публичны код и документация; лекции, секреты и локальные артефакты остаются вне Git. Рабочие файлы, незакоммиченные правки, история чата, установки Python и модели автоматически не переносятся. На каждом компьютере должна быть отдельная копия проекта. Не синхронизировать рабочую папку вместе с .git/.venv через облачный диск.

## Подготовка первого компьютера

Локальный репозиторий уже инициализирован с веткой main. Проверь текущее состояние: инструкция не означает, что первый коммит или отправка уже выполнены.

```powershell
git status
git remote -v
```

Если имя/email не заданы, согласуй их с пользователем. Следующие команды — шаблоны, значения нужно заменить. Они меняют только этот репозиторий:

```powershell
git config --local user.name "ИМЯ АВТОРА"
git config --local user.email "EMAIL АВТОРА"
```

Удалённый репозиторий уже выбран: https://github.com/plus-vibe/ai-project-new.git. При настройке нового проекта создавай пустой репозиторий без README, лицензии и .gitignore, чтобы не создавать вторую независимую историю; публичность согласуй отдельно. Пароли и токены не вставлять в файлы или чат; использовать авторизацию Git на устройстве. Перед первым коммитом проверь `git diff --cached` и `git diff --cached --name-only`: там не должно быть лекции, локальных ответов модели, .env или .venv. Индексируй конкретные файлы; не применяй `git add -f` к исключённым данным.

После подготовки индекса и указания автора:

```powershell
git commit -m "Initialize Lecture Notes AI scaffold and collaboration guide"
git remote add origin https://github.com/plus-vibe/ai-project-new.git
git push -u origin main
```

Если origin уже существует, сначала проверь его; не повторяй remote add и не заменяй адрес автоматически. Ошибка push не означает, что данные опубликованы. Не использовать force-push.

## Второй компьютер

```powershell
git clone https://github.com/plus-vibe/ai-project-new.git lecture-notes-ai
cd lecture-notes-ai
git status
git log -5 --oneline
```

Клонируй в новую папку, а не поверх существующей работы. Открой эту папку в IDE. Прочитай AGENTS.md, README.md, docs/rules.md, docs/roadmap.md и последние записи docs/devlog.md.

Проверь установленные Python и Ollama. На первом компьютере работает Python 3.14.2 по пути .venv\Scripts\python.exe, но на другом это нужно проверить заново. Для инструментов каркаса достаточно стандартной библиотеки; pyproject.toml/uv.lock ещё нет, устанавливать зависимости приложения пока не из чего.

Пример для Windows при рабочем Python launcher:

```powershell
py --version
py -m venv .venv
.\.venv\Scripts\python.exe -X utf8 tools/check_harness.py
```

Если py недоступен, использовать найденный полный путь к Python. Не копировать .venv с первого компьютера. Флаг -X utf8 нужен текущему harness на Windows с системной cp1251; настройки системы он не меняет. Для Linux/macOS эквивалент проверки: `python3 -X utf8 tools/check_harness.py`.

Передай исходный ZIP отдельно приватным способом в data/private/test_note.zip. Папку при необходимости создай. Для проверки идентичности файла на обоих компьютерах сравни вывод:

```powershell
Get-FileHash data/private/test_note.zip -Algorithm SHA256
.\.venv\Scripts\python.exe -X utf8 tools/inspect_zip.py data/private/test_note.zip
```

artifacts/m1-review/review.md и PNG тоже локальные: если нужна именно текущая подборка, передай папку отдельно. Модели Ollama не входят в Git: доступность сервера и установленных моделей проверяется заново; ничего не скачивать без задачи пользователя. Не переносить секреты через репозиторий.

## Работа по очереди

Заверши текущий шаг, проверки, devlog, commit и push на одном компьютере до начала следующего шага на другом.

Перед изменениями:

```powershell
git status --short --branch
git pull --ff-only
```

Pull выполняется только в чистом рабочем каталоге и с настроенной upstream-веткой. Если есть правки или Git требует merge/rebase, остановись и разберись в расхождениях; не очищай папку автоматически. После задачи проверь diff, добавь конкретные файлы, сделай коммит и push. Незакоммиченная работа на другом компьютере не появится.

## Одновременная работа

Каждой сессии назначь отдельную задачу, ветку и список файлов. Например, одна сессия занимается кодировкой harness, другая — документацией протокола эксперимента. Обе сессии не должны одновременно утверждать эталоны или менять один файл.

Из чистой обновлённой main:

```powershell
git switch main
git pull --ff-only
git switch -c task/ИМЯ_ЗАДАЧИ
```

После реализации и проверок: commit, затем `git push -u origin task/ИМЯ_ЗАДАЧИ`. Для объединения открыть pull request в main и проверить итоговый diff. Если документация, промпты или код изменились при объединении, повторить релевантные проверки на объединённом состоянии. Для harness:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/check_harness.py
```

docs/devlog.md общий: добавляй отдельную запись с задачей и веткой, сохраняй записи другой сессии при конфликте. Не используй автоматический выбор всей «нашей» или «чужой» версии. После объединения получить main на обоих компьютерах. Первый коммит в новую task-ветку делать после обновления main; незавершённые изменения не переносить переключением веток вслепую.

## Особенность первого компьютера: владелец .git

При создании .git из sandbox и последующем запуске Git под другим пользователем возможна ошибка dubious ownership. В этой сессии проверен ограниченный обход для одной команды: `git -c safe.directory=C:/private_project status`. При необходимости тот же параметр можно добавить перед подкомандой Git. Он доверяет только этой папке на время команды и ничего не записывает в глобальные настройки. На втором компьютере после обычного clone под своим пользователем проблема не ожидается; доступность всё равно проверить. Не добавлять safe.directory=* и не менять глобальные настройки автоматически.

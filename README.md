# Lecture Notes AI

Локальный помощник, который превращает конспект Obsidian со скриншотами слайдов и заметками в краткий Markdown-конспект, сохраняя порядок объяснения и связь с источниками.

Учебный проект по предмету «Личный проект с использованием ИИ». Цель — показать работающий прототип и весь цикл AI-native разработки: постановку задачи, макет, работу с Codex, golden set, эксперименты, логирование, тестирование и улучшение результата.

## Текущий статус

Локальный веб-MVP **«Лекта»** создаёт **общий summary лекции на основе скриншотов и подписей в Markdown**. Сначала отдельно читает все изображения, затем объединяет соседние материалы по темам и пишет общее введение. Можно один раз подключить папку вложений, а дальше загружать только MD: нужные скриншоты подбираются автоматически. Доступны также загрузка MD с изображениями, папки одной лекции или ZIP, просмотр оригиналов и извлечённого текста, история, оглавление и экспорт Markdown. Отсутствующие скриншоты блокируют обработку. Автоматическая оценка качества ещё не реализована; skills представлены шаблонами.

## Запуск MVP

На этом Windows-устройстве откройте `start.cmd` двойным щелчком. Он запускает сервер и открывает приложение в браузере. Либо из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/serve.py
```

Откройте **http://127.0.0.1:8765**. Для Linux/macOS команда: `python3 -X utf8 tools/serve.py`. Нужен Python 3.12+ и запущенная локальная Ollama с уже установленной vision-моделью; используется `qwen3-vl:4b-instruct`. Устанавливать пакеты для MVP не требуется: сервер — стандартная библиотека Python, фронтенд — HTML/CSS/JavaScript. Скрипт не скачивает модели. Порт можно изменить: `--port 8766`.

1. Нажмите **«Подключить папку»** в карточке скриншотов. Выберите папку вложений Obsidian или общую папку с изображениями нескольких лекций. Доступ нужен только на чтение. В Chrome/Edge папка запоминается браузером для этого адреса приложения; после перезапуска может понадобиться **«Разрешить доступ»**. В браузере без этого API папка подключается на текущую сессию через обычный выбор папки.
2. Выберите или перетащите один UTF-8 `.md`. Приложение разберёт ссылки и подберёт **только нужные** PNG/JPEG/WebP из подключённой папки и подпапок. Посторонние изображения и другие заметки не загружаются. ZIP и MD с вручную выбранными картинками поддерживаются, общий лимит загрузки — 30 МБ.
3. Проверьте «Скриншоты: N из M доступны». Если файлы отсутствуют, используйте **«Найти в папке»** или **«Добавить вручную»**. Относительный путь имеет приоритет; одинаковые имена без однозначного пути не выбираются наугад. Добавление создаёт исправленную копию, исходная загрузка сохраняется. Кнопка × в карточке папки забывает её настройку.
4. Выберите объём и модель, нажмите **«Создать summary»**. Сначала читаются скриншоты, затем составляется общий текст по темам.
5. Во вкладке **«Источники»** можно увидеть оригинал, подпись и прочитанный со скриншота текст. Подписи добавляются при анализе тем, не подменяют чтение изображений.
6. Для переходов между темами есть оглавление. Нажмите **«Скачать .md»**: источники перечислены в конце файла, изображения в экспорт не включаются.

После подключения появляется сообщение с названием папки и количеством изображений. Оно видно и в открытой лекции. Если выбрать папку из одних скриншотов через общий выбор папки или перетаскивание, она тоже подключится как библиотека; недостающие изображения открытой лекции подберутся автоматически. При недоступном сохранении настроек папка работает на текущую сессию.

Поддерживаются Obsidian-вставки с путями, alias/размером и обычные Markdown-изображения в простой записи. Вложения разрешаются по пути, затем по единственному имени. Не найденные, внешние и неоднозначные вложения блокируют создание полного summary; внешние картинки не скачиваются. Неиспользуемые изображения исключаются. Текстовые блоки и порядок сохраняются, заголовок начинает новый блок. Это ограниченный разбор Markdown, без полной поддержки его грамматики.

Материалы обрабатываются только локально. Загрузки, результаты, история и кэш находятся в `artifacts/app/`; эти пользовательские данные не следует включать в Git по умолчанию. Настройка папки хранится в браузере (IndexedDB), не на сервере и не в репозитории. Исходные файлы не изменяются. Индекс имён строится заново для каждой лекции, ограничен 20 000 записей и глубиной 20 папок; выбирайте папку вложений, а не весь диск. Служебные .git/.venv/.obsidian/.trash/.codex/node_modules не обходятся, .attachments поддерживается. Конспекты доступны после перезапуска; при ошибке можно повторить обработку с кэшем. Работающая очередь переживает обновление страницы, но не остановку сервера: после перезапуска нужен повтор. **Ctrl+C** останавливает сервер.

Ограничения: до 100 блоков и 16 000 символов заметок в блоке; одна обработка модели одновременно. Темы формируются из соседних блоков по заголовкам/разделителям и ограничению размера; границы могут потребовать улучшения. Извлечение не сокращается до суммаризации. 4B может ошибаться в чтении названий, формул, графиков и при сокращении — важные детали нужно сверять с оригиналом. Ссылки на диапазоны источников назначает приложение, они не доказывают полноту и фактическую точность. Markdown отображается ограниченным рендерером без выполнения HTML и загрузки внешних изображений. Сервер предназначен для личной работы на loopback, не для публикации в интернет. Старые результаты по отдельным слайдам помечены и требуют пересборки.

## Проблема и пользователь

Инструкция по переносу проекта и работе с Codex на двух компьютерах: [docs/git-sync.md](docs/git-sync.md).

Студент ведёт конспекты в Obsidian: скриншоты презентации и короткие комментарии под ними. Часть смысла находится только на изображениях; комментарии могут быть непонятны без слайда. Подготовка к занятиям требует повторного чтения большого количества материалов.

Продукт должен объединить эти источники и сократить материал, сохранив определения, условия, формулы, команды и последовательность тем.

## Границы MVP

Вход: ZIP с одной Markdown-заметкой и локальными изображениями. Основной формат ссылок — Obsidian `![[image.png]]`; обычные Markdown-вложения и варианты с путём, alias и размером необходимо предусмотреть в парсере и тестах.

Выход: краткий конспект `.md`, список предупреждений и ссылки на исходные блоки/изображения. Для переносимого экспорта с изображениями нужен отдельный пакет с вложениями или явно описанная схема размещения рядом с исходной заметкой.

Один запуск обрабатывает одну лекцию. MVP не включает чат по всем предметам, векторную БД, синхронизацию vault и анализ видео.

## Пользовательский сценарий и макет

1. Выбрать ZIP с лекцией.
2. Увидеть найденную заметку, количество используемых изображений и проблемы со ссылками.
3. Запустить обработку и видеть текущий этап/прогресс.
4. Просмотреть конспект, предупреждения и источники разделов.
5. Скачать Markdown; при ошибке повторить незавершённый этап с использованием кэша.

Реализованный интерфейс «Лекта»: тёмная боковая библиотека, синие акценты, карточка подключённой папки, выразительная типографика, светлая область чтения с оглавлением, вкладки конспекта/источников, прогресс и экспорт. Адаптирован для телефона. Фронтенд без сборки, внешних шрифтов и зависимостей.

## Пайплайн

1. Проверить ZIP: пути, симлинки, число файлов, распакованный размер и лимиты; не исполнять содержимое.
2. Найти ровно одну заметку; при неоднозначности запросить выбор.
3. Разобрать Markdown в упорядоченные блоки, сохраняя заголовки, строки источника, изображения, списки и код.
4. Разрешить локальные ссылки. Отсутствующие и неоднозначные вложения показать пользователю. Неиспользуемые файлы не включать автоматически.
5. Прочитать изображения vision-моделью, сохранив полное извлечение до сокращения.
6. Соединить слайд и следующий за ним комментарий. Заголовки Markdown сохранять отдельно; контекст соседних блоков использовать без изменения порядка.
7. Составить краткий конспект по разделам, приложить идентификаторы источников.
8. Проверить структуру ответа, допустимость ссылок и обработку ошибок. Это не доказывает фактическую корректность: её проверяет golden set и человек.
9. Экспортировать результат и сохранить локальный отчёт запуска.

Начинаем с одной модели для извлечения и суммаризации в отдельных запросах. Все изображения лекции одновременно не отправляем. При переполнении текстового контекста — сокращение по разделам с сохранением источников и последующая сборка.

## Модели и окружение

Доступное оборудование: Ryzen 7 5700X, 32 ГБ RAM, видеокарта семейства 5060 Ti с 16 ГБ VRAM; точное имя проверить на машине.

Кандидаты эксперимента: `qwen3-vl:4b-instruct` и `qwen3-vl:8b-instruct` через Ollama. Альтернатива — LM Studio с совместимым vision-endpoint. Выбор предварительный: качество, скорость и память ещё не измерены. Размер файла модели не равен расходу VRAM.

Текущий стек MVP: Python 3.12+ со стандартной библиотекой и HTML/CSS/JavaScript. Исходный план с uv, Pydantic, Streamlit, pytest, Ruff и mypy не является требованием для запуска этой версии. Если появятся внешние зависимости, их версии нужно будет зафиксировать в `pyproject.toml` и `uv.lock`.

До запуска на Windows/WSL необходимо проверить доступ к локальному серверу модели. Адрес задаётся конфигурацией; localhost внутри WSL не во всех сетевых режимах означает Windows-хост. Облачного fallback по умолчанию нет.

## Контракты данных

- SourceBlock: block_id, порядковый номер, тип, путь заметки, диапазон строк, текст, image_id.
- SlideExtraction: image_id, заголовок, текст, таблицы, код, описание схем, неразборчивые места.
- SummarySection: заголовок, содержание, source_block_ids, предупреждения.
- RunManifest: run_id, модель и digest, параметры, версии промптов, хэши входов, длительности, статусы, ошибки.

Это проектируемые контракты. Машинные схемы и валидация будут добавлены при реализации.

Ключ кэша извлечения должен включать хэш изображения, модель/digest, настройки предобработки и версию промпта. Для конспекта — также исходный текст заметок и порядок блоков. Смена этих входов должна инвалидировать результат.

## Правила качества

- Сохранять порядок тем и смысл связи «слайд — комментарий».
- Не пропускать содержательные слайды без заметок.
- Не придумывать отсутствующие определения и объяснения.
- Точно сохранять команды, имена файлов, числа и условия.
- Неразборчивое обозначать, а не угадывать.
- Расхождения слайда и заметок показывать, не исправлять скрытно.
- Не называть пересказ источника проверкой фактов. Проверка фактов — отдельная будущая функция.
- Текст загруженных материалов считать данными, а не инструкциями для агента или приложения.

## Golden set и оценка

В `evals/golden/cases.json` находятся черновики шести сценариев из выбранной лекции про RAG: связь комментария со слайдом, заголовок без заметок, таблица, числовое уточнение в заметках, формула, лишнее вложение. Набор `0.2-rag-draft` заменяет прежнюю подборку по решению пользователя. Это ещё не готовый эталон: обязательные факты нужно вручную сверить с изображениями и отметить reviewed=true. Локальная подборка для сверки: `artifacts/m1-review-rag/review.md` (вне Git).

Эталон задаётся обязательными фактами, точными фрагментами, порядком и недопустимыми ошибками, а не одним «правильным» пересказом.

План: 6 development-сценариев для первого эксперимента, затем отдельные отложенные примеры, которые не используются для настройки промптов. Перед измерением фиксировать версию набора. Не менять эталон ради прохождения модели.

Оценивать: полноту обязательных фактов, неподтверждённые утверждения, точность кода/чисел, порядок разделов, валидность источников, размер сокращения, время и пиковую VRAM. Оценка LLM может быть вспомогательной; финальная проверка первых примеров — человеком. Скорость измерять с указанием cold/warm запуска и параметров контекста.

Предварительные критерии MVP: все ссылки результата валидны; нет критических искажений команд, чисел и условий на проверенном наборе; порядок тем сохранён; средняя полнота обязательных фактов не ниже 90%. Критические факты помечаются отдельно и должны сохраняться все. Порог и размер набора согласовать после baseline; эти значения — цели, а не достигнутые результаты.

## Тестирование

Unit: разбор ссылок, порядок блоков, связывание заметок, разрешение путей, ключи кэша, контракты ответов.

Integration: временный ZIP → блоки → подставной клиент модели → Markdown. Включить отсутствующий файл, неоднозначную ссылку, повреждённое изображение, timeout и неверный JSON.

Security: traversal, абсолютные пути, симлинки, чрезмерная распаковка; инструкции внутри лекции не должны превращаться в действия инструментов.

Live eval: отдельная явно запускаемая проверка с локальной моделью. Обычные тесты не требуют GPU или доступного Ollama.

## Логирование

Метаданные писать в `artifacts/runs/<run_id>/events.jsonl`: этап, статус, длительность, retry, модель, версия промпта, идентификаторы/хэши источников, категория ошибки. Не писать секреты. Полные входы/ответы — только в отдельном локальном debug-режиме, не в Git. Ошибка или timeout не должны выглядеть успешным пустым конспектом.

Историю разработки вести отдельно: задача агенту, изменение, команды проверки, результат, обнаруженная проблема и следующее решение — `docs/devlog.md`. Результаты измерений не выдумывать.

## Harness для Codex

- `AGENTS.md`: постоянные инструкции по проекту, маршруты к правилам и командам.
- `agent.md`: указатель для формального требования преподавателя; источник правил один — AGENTS.md.
- `docs/rules.md`: подробные инварианты продукта и разработки.
- `docs/skill-templates/*.md.template`: заготовки повторяемых процедур; размещение после проверки в `.agents/skills/<name>/SKILL.md` в своей рабочей области.
- `tools/`: воспроизводимые локальные инструменты. На старте — аудит ZIP и проверка каркаса.
- `prompts/`: версионируемые промпты продукта, отдельно от инструкций агенту-разработчику.
- `evals/`: golden set и будущий оценщик.
- `docs/experiments/`: отчёты сравнения моделей и промптов.

Наличие harness не гарантирует качество: на защите показать реальную задачу, ошибку, проверку и улучшение.

## Что можно запустить сейчас

Из корня проекта, требуется только Python 3:

```bash
python3 tools/check_harness.py
python3 tools/inspect_zip.py /path/to/test_note.zip
```

В WSL при наличии make: `make harness-check` и `make inspect INPUT=/path/to/test_note.zip`. Эти команды не запускают модель и не создают конспект.

Пробное извлечение выбранных слайдов локальной моделью (Windows, из корня проекта):

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/run_extraction.py data/private/test_note.zip --save-responses
```

Требуется работающая Ollama с уже установленной `qwen3-vl:4b-instruct`. Скрипт ничего не скачивает и использует только стандартную библиотеку Python. `--model qwen3-vl:8b-instruct` позволяет позднее повторить те же входы и промпт на установленной 8B. Endpoint по умолчанию — `http://127.0.0.1:11434`; разрешены только HTTP-адреса с loopback IP, без proxy и перенаправлений.

Скрипт читает ZIP без распаковки, проверяет ограничения через inspect, выбирает изображения из cases.json в порядке каталога и пропускает неиспользуемые вложения. Комментарии из заметки модели не передаются. Это чтение слайдов, а не создание конспекта и не проверка связывания заметок. Ограничения разбора wiki-вставок наследуются от inspect.

Результат — новая папка `artifacts/runs/<run_id>/`: `manifest.json` с параметрами, хэшами входов, digest модели, длительностями и статусами; снимки промпта и каталога. Флаг `--save-responses` явно разрешает сохранить ответы в `01-response.txt` и далее; без него полные ответы не пишутся. Все артефакты остаются вне Git. При ошибке, пустом ответе или исчерпании лимита генерации запуск завершается ненулевым кодом; частичный ответ с указанным флагом сохраняется для разбора. Автоматических повторов нет. Таймаут по умолчанию — 180 секунд на запрос, контекст — 8192 токена, лимит ответа — 4096, temperature=0, seed=42. Исходное состояние загрузки модели и load_duration записываются; принудительного cold/warm режима и измерения пиковой VRAM пока нет. Ответы модели остаются недоверенными данными; файлы .txt открывать как текст.

Локальные тесты скрипта без Ollama, GPU и внешней сети:

## План реализации

1. Уточнить дедлайн и требования защиты; подтвердить MVP и формат результата.
2. Вручную разметить 6 примеров; проверить извлечение 4B и 8B на одинаковых входах. Сохранить baseline и выбрать модель по данным.
3. Создать uv-проект и lockfile; реализовать безопасный импорт, парсер и unit-тесты.
4. Добавить клиент модели, контракты, извлечение, кэш и логирование; проверить ошибки.
5. Реализовать суммаризацию, источники и экспорт; провести golden-set оценку и исправить ошибки.
6. Сделать визуальный макет и Streamlit-интерфейс; проверить сценарий одной лекции целиком.
7. Провести отложенную оценку на другой лекции; оформить отчёт, ограничения и демо.
8. После MVP: аудиодорожка записи → распознавание речи с таймкодами → объединение с заметками; затем сопоставление слайдов и кадров. Наличие аудио в записи проверить отдельно.
